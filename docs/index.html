PROJECT 01 / AUTONOMOUS MOBILE ROBOT 통합 시험 단계
ROS 2 JazzyNav2Python · rclpy ArUco · LiDAROpenCR · Arduino C++TurtleBot3

스마트팜 운송로봇 — 주행 · 정밀 도킹 · 바구니 구동부

예찰 → 수확 → 운송 → 선별로 이어지는 스마트팜 다중 로봇 시스템(ManyFarm)에서, 수확로봇에게 파프리카를 받아 선별장까지 옮겨 쏟는 운송로봇 transport_01을 맡았습니다.

목표
운송로봇 한 대가 주행 → 정밀 도킹 → 받기 · 쏟기까지 실물에서 동작하게 만들기.
내 역할
운송로봇 공동 담당 — 9/10–10/12 주행 · 정밀 도킹(요구사항 · FSM 설계, Nav2 주행, ArUco + LiDAR 도킹, 팀 라우트서버 연동) · 10/13~ 바구니 구동부(기구 제작, 전원 · 배선, OpenCR 펌웨어, ROS 2 브리지 노드, URDF 실물 반영)
팀 구성
7인 팀 · KDT 로봇 3기 최종 프로젝트 · 2026.09 ~ 2026.11 · 10/14 이후 주행 · 도킹은 팀원이 이어받음
플랫폼
TurtleBot3 Waffle Pi (Raspberry Pi 4, OpenCR 1.0, LiDAR, Pi 카메라 V2) + 직접 만든 적재 바구니

A. 주행 · 정밀 도킹 (9/10 – 10/12)

  1. SEARCH회전하며 마커 탐색
  2. TRACK먼 마커로 접근
  3. FINE가까운 마커로 정지
  4. ALIGNLiDAR 면 정렬
  5. PUSH · DONE짧게 직진 후 완료
  • 설계요구사항 · 기능 · 비기능 · 인터페이스 · 개발 단계 · State 설계 문서 6종 작성. 미션 FSM은 정상 9개 State + 전역 ERROR/ESTOP, Nav2와 정밀 제어기의 제어권을 하나로.
  • 주행폐쇄망 TurtleBot3를 실물에서 달리게 만듦 — 시계 동기화, 바구니 기둥을 지우는 LiDAR 필터, 최대 속도 0.13 m/s 제한. SD 카드 무인 설치 스크립트(13단계, 이미 된 단계는 건너뜀).
  • 인식Pi 카메라(IMX219) 1280×720 캘리브레이션, 마커 크기별 인식 거리 실측 (10 cm 마커 0.3–2 m). 근거리에서 마커가 화면을 넘치는 한계 때문에 장소마다 마커 2개 — 먼 마커로 방향, 가까운 마커로 정지.
  • 도킹dock.py 하나로 주차장 · 수확로봇 · 선별장을 처리하고 장소 값은 sites.yaml로 분리. 마지막 각도는 카메라 대신 LiDAR로 정면 면의 기울기를 재서 맞추고, 정렬 후 직진 · 후진 이탈(UNDOCK)까지.
  • 검증실물 1회차 실패(접근 중 마커 놓침)를 분석한 뒤, 가상 카메라(투영 + 노이즈 + 지연 + 바퀴 편차) 폐루프 시뮬레이터를 만들어 시작 위치 7종으로 반복 검증하고 재설계.
  • 연동팀 라우트서버(수정 없이 사용) 위에 운영 스크립트(wf 이동 · 도킹 · 이탈) 작성, DDS IP 직접 지정, Pi 4 부하 감소. 10/9 설치 스크립트 포함 인수인계 패키지로 전달.

B. 바구니 구동부 (10/13 ~) — 받기 · 운반 · 쏟기

  • 기구팀 CAD를 바탕으로 출력 부품을 19 → 10개로 합치고, 축 구멍을 Ø8.4로 키워 미끄럼 베어링 역할. 윗덮개(랙 · 피니언 슬라이드) · 앞문 · 틸트 3개 구동부 조립. 틸트 모터 배송 지연 → 같은 배선으로 12V 리니어 액추에이터로 교체.
  • 전원기구 전용 배터리를 분리해 서보 · 리니어 전류가 OpenCR · 라즈베리파이 전원을 흔들지 않게 설계. DC-DC 5V, L298N, GND 한 점 공통, 로커 스위치로 기구 전원만 차단. 배선도 v1 → v3, 전선 라벨 체계.
  • 펌웨어TB3 순정 주행 펌웨어 위에 액추에이터 모듈을 얹은 통합 펌웨어 — OpenCR 한 장으로 주행 + 기구. delay() 없는 millis 상태머신, USB는 주행이 쓰고 기구 명령은 UART로 분리, 회신 규칙 OK(접수) · DONE(완료) · STOPPED · ERR · READY.
  • 제어서보가 360° 연속회전형으로 확인돼 위치 대신 시간 제어로 전환. 덮개는 문틀에 끼어 전진 0.1 s / 후진 0.05 s 끊어치기, 틸트는 내림을 1 s 길게 잡아 매번 바닥 리미트로 기준점 복귀. 동작마다 시간 상한 + 강제 정지.
  • ROS 2브리지 노드 transport_device_bridge — 서비스 6개 (lid_open/close · gate_open/close · unload · stop), 동작이 끝나야 응답. 실패 시 stop 후 이유와 함께 실패 반환. 운송 노드는 서비스 호출만 하면 됨.
  • 모델틸트 · 앞문 각도, 경첩 높이, 카메라 위치(9° 틀어짐) 등을 실측해 실물 반영 URDF 작성 — 기둥이 LiDAR를 가리는 것까지 시뮬레이션에서 재현하기 위함.

검증 · 결과

  • 기구가 움직이는 동안에도 주행 통신 유지 — 약 68초 동작 중 /odom 평균 20.0 Hz, 최대 간격 0.064 s (실물, 10/23)
  • 덮개 · 앞문 5회 반복 완전 개폐, 비상 정지 즉시 정지, 내용물 넣고 적재 쏟기 통과 (실물)
  • 브리지 노드 사전 시험 16/16, 로봇에서 실제 서비스 호출 통과
  • 폐쇄망 Nav2 주행, 주차장 도킹 동작 확인 (실물)
  • 도킹 정밀도는 오프라인 시뮬레이터 값 — 선별장 좌우 ±1.4 cm, 수확로봇 ±0.6 cm. 실물 반복 성공률은 측정하지 않아 쓰지 않음

트러블슈팅

  • Nav2가 목표를 거절 — 폐쇄망이라 로봇 시계가 부팅마다 약 20일 틀어져 TF 시각 무효 → PC를 시간 서버로, bringup에 시계 동기화
  • 도킹 각도 오차 — 마커만 보면 시뮬레이션에서도 최대 ±11°, 카메라도 약 8° 틀어져 장착 → 마지막 각도는 LiDAR 면 정렬로 분리
  • 서보가 멈추지 않음 — 라벨로 구분 안 되는 360° 연속회전형 → 손으로 돌려 확인 후 시간 제어 펌웨어로 변경
  • UART 무반응 · 업로드 CRC Fail — 라즈베리파이 시리얼 콘솔이 포트 점유 → 해제. 업로드 실패는 순정 업로더로 보드부터 확인 후 1.5 KB 줄여 해결
  • 바구니 기둥이 장애물로 잡힘 — 0.20 m 미만 점 제거 필터, AMCL · costmap · 충돌 감시를 같은 토픽으로 통일
  • PC · 로봇 통신 실패 — 공유기가 멀티캐스트 차단 → Fast DDS에 IP 직접 지정
협업 범위 관제 · 라우트서버 · Zenoh 연결은 팀 코드이며 수정 없이 그 위에 얹었습니다. 10/14 이후 주행 · 도킹과 FSM 변경은 팀원이 이어받았고, 운송 미션 노드 · 관제와의 통합 시험은 팀과 함께 진행 중입니다.

배운 점

실물은 시뮬레이션에 없던 문제로 막힙니다. 그때마다 한 번에 하나만 바꾸고, 순정 펌웨어 · 닫힌 위치 같은 정상 기준으로 먼저 되돌려 원인을 좁혔습니다. 경계를 나누는 설계(주행은 USB, 기구는 UART · 운송 노드는 서비스만, 시리얼은 브리지가)가 디버깅과 협업을 쉽게 만들었고, 실물 · 시뮬레이션 · 미검증을 구분해 말하는 습관이 팀과 발표의 신뢰를 지켰습니다.

PROJECT 02 / EMBEDDED ROBOT
STM32F411C · HALL298N 4WD PCA9685하드웨어 설계

ChaPaRi — 모바일 물품 회수 로봇

스마트폰으로 이동·접근·잡기·운반을 수행하는 4WD 차량 + 5축 로봇팔 통합 로봇.

목표
이동만 가능한 RC카와 작업영역이 좁은 고정 로봇팔을 결합해 “접근→잡기→운반→놓기”를 하나의 로봇으로.
내 역할
RC카 주행 제어 · 로봇팔 서보 각도 제어 · 하드웨어 설계·전원 회로
팀 구성
5인 팀 · RC카·로봇팔 제어 및 하드웨어 파트 담당

담당 구현

  • 주행L298N으로 좌우 DC모터 4개를 그룹 차동 구동. TIM2 20 kHz PWM + 방향 GPIO로 전진·후진·회전·곡선 주행 구현.
  • 로봇팔PCA9685(I2C) 6채널 50 Hz 서보 PWM으로 MG996R · SG90 서보 6개 구동. 앱 각도(−90~+90°)를 서보 각도로 매핑하는 기초 제어.
  • 하드웨어서보용 · 차량용 2S 배터리 팩 전원 분리 설계. XL4015 강압, PCA9685 V+에 1000 µF 안정화, 공통 GND 결선, STM32 핀 배치까지 직접.

검증 · 결과

  • 앱 명령으로 차량 주행 + 로봇팔 파지·운반 동작 실동작 성공
  • 전원 분리 · 공통 GND 결선 검증, 로봇팔 6축 개별 구동 확인
  • STM32 Flash 18.4% (72 KB / 384 KB) · RAM 22.2% 사용

트러블슈팅

  • 서보 부하 시 떨림 — 손목 회전·그리퍼 서보에 부하가 걸리면 순간적으로 떨림 발생. 긴 케이블과 커넥터 저항으로 서보 단자 전압이 순간 강하하는 것이 원인 → 커패시터 적용과 전원 배선 점검으로 해결
협업 범위 Yaw PID(직진 안정화) · 서보 3점 보정 · S-curve · 티칭 시스템 · Flutter 앱 · 16바이트 통신 프로토콜 설계는 팀원이 담당했습니다.

배운 점

문제가 발생했을 때 원인이 소프트웨어인지 하드웨어인지 구분하는 과정이 생각보다 어려웠습니다. 하지만 원인을 하나씩 확인하고 해결하면서 시스템 전체를 바라보는 시야를 넓힐 수 있었습니다. 특히 IMU 기반 PID 제어를 가까이서 다루고 로봇팔 서보 구동을 직접 구현해보며 센서와 제어 기술에 대한 흥미가 커졌습니다. 제한된 환경에서 소프트웨어와 하드웨어를 통합하고 성능을 개선하는 과정에서 큰 보람을 느꼈고, 앞으로 더 다양한 센서를 활용한 제어 시스템을 만들어보고 싶어졌습니다.

PROJECT 03 / ON-DEVICE AI · SAFETY
Raspberry Pi 5YOLO11MobileNetV3 Python멀티라벨 분류

Safe Eye — On-Device AI 산업 현장 안전 감지

고정 카메라 비전으로 작업자의 PPE(안전모·안전조끼) 미착용과 위험구역 접근을 네트워크 없이 단말에서 실시간 감지.

목표
추론이 단말에서 끝나는 On-Device 안전 비전 — PPE 판별과 위험구역 판정을 동시에.
내 역할
PPE MLC 모델 설계·학습 · 위험지역 감지 시스템
팀 구성
4인 팀 · MLC 모델 & Danger Zone 파트 담당

담당 구현

  • MLCperson 크롭을 MobileNetV3Large 멀티라벨 헤드(헬멧·조끼 Sigmoid×2)로 분류. 상태 코드별 분포가 극단적(01 코드 ≈900장 vs 10 코드 ≈25,000장)인 문제를 균등 샘플링 + Stratified 3분할로 잡아 학습을 안정화.
  • 위험구역YOLO11n으로 위험 표지판을 탐지 → bbox를 확장해 Danger Zone polygon 생성 → person bbox 하단(발 위치)이 polygon에 들어오면 즉시 DANGER 경고. 표지판은 고정 위치라 30프레임 단위 탐지 후 캐시 재사용으로 자원 절약.

검증 · 결과

  • MLC Validation 정확도 — 헬멧 91.0% · 조끼 91.8% (KPI 80% 상회)
  • 위험구역 감지 YOLO11n — Precision 1.000 · Recall 0.940
  • OD vs MLC를 동일 person 박스·독립 GT(1,477명)로 공정 비교해 환경별 최적 모델 선정 근거 제시
협업 범위 PPE OD 모델 · 하드웨어(IR·카메라·스피커) · 학습/평가 데이터 전처리 · 시스템 통합·프론트엔드 대시보드는 팀원이 담당했습니다.

PROJECT 04 / PLC · FACTORY AUTOMATION
Mitsubishi Q03UDVQD77MS2GX Works2 GT Designer3서보 위치결정

PLC 기반 금속·비금속 분류 적재·배출 자동화

금속과 비금속을 구별해 창고에 층별 적재하고, 필요 시 다시 배출하는 자동화 시스템. 서보 위치결정과 HMI, 안전 설계까지 하나의 공정으로 구현.

목표
재료 판별 → 창고 층별 적재 → 배출까지 전 공정을 PLC로 자동화.
스택
Mitsubishi Q03UDV · QD77MS2 서보 위치결정 · GX Works2(래더) · GT Designer3(GOT2000 HMI)

담당 구현

  • 모션QD77MS2 서보 위치결정 모듈로 층별 적재·흡착 위치 제어(INCP 상대 위치결정).
  • HMIGT Designer3로 동작상태·적재현황 램프, 원점복귀·JOG 수동조작·배출 버튼 구성.
  • 안전M987로 자기유지(M100·M199)를 끊어 PLC를 즉시 정지시키는 비상정지 설계.

트러블슈팅

  • 서보 층 이동 실패 — 다음 소재가 들어와도 위층으로 안 올라가고 1층에서 적재만 반복 → 조건 수정 후 정상 동작 확인
  • INCP 중복 실행 — 배출 시 자기유지 해제 타이밍이 안 맞아 INCP D값이 중복 실행 → 초기화 조건에 동작완료 b접점을 추가해 초기화 중 INCP 차단

결과

  • 재료 판별·적재·배출 전 공정 자동 동작, 비상정지 확인
  • 현장 인수인계용 One-paper 유지보수 매뉴얼 작성 (초기화 순서 정리)
